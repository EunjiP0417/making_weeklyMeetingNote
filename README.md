# 주간 회의자료 자동 취합

Windows용 한/글 자동화(`pyhwpx`)와 Tkinter로 만든 생방기술1·2 주간 회의자료 취합 프로그램입니다. 부서별 회의자료를 만든 뒤 두 부서의 결과를 합쳐 생방기술국 최종본까지 생성할 수 있습니다.

현재 적용된 조건을 검토하거나 수정할 때는 [취합 조건 정리](docs/취합_조건_정리.md)를 참고하세요. 각 조건에 번호를 붙여 입력 범위·부서 경계·서식 보존·저장 규칙과 현재 제한을 정리했습니다.

## 주요 기능

- **모드 선택:** 우측 상단의 `생방기술1` / `생방기술2` / `생방기술국` 버튼으로 전환합니다. 기본값은 생방기술2이고 선택한 버튼을 검정 배경·흰색 글씨로 강조합니다. 모드를 바꾸면 업무 목록을 초기화하므로 다시 불러와야 합니다. 불러오기·생성 중에는 전환할 수 없습니다.
- **추진실적 이월:** 지난주 최종본의 추진계획에서 선택 부서의 업무만 가져와 이번 주 추진실적으로 넣습니다. 자동 구분 제목이 없으면 업무 제목 목록에서 경계를 선택합니다. 처음에는 지난주 순서로 표시하며, 이후 순서를 변경할 수 있습니다.
- **추진계획 취합:** 이번 주에 추가한 여러 HWP/HWPX 파일에서 추진계획을 가져옵니다.
- **생방기술국 최종 취합:** `생방기술국`은 부서별 파일 두 개를 선택하는 별도 입력 화면을 표시합니다. 처음에는 두 파일의 추진실적끼리, 추진계획끼리 생방기술1 → 생방기술2 순서로 불러옵니다. 이후 다른 모드와 같이 드래그·이동 버튼·`Alt+↑/↓`로 순서를 바꿀 수 있으며, 저장할 때 각 항목을 최종 순서에 따라 독립적으로 1번부터 번호를 매깁니다. 이 모드는 지난주 계획을 이월하지 않습니다.
- **업무 순서 변경:** 왼쪽 `업무 제목`, 오른쪽 `파일명`을 별도 열로 표시합니다. 열 경계를 드래그해 폭을 조절할 수 있고, 두 항목 모두 어느 열에서든 드래그, 위/아래 버튼, `Alt+↑/↓`로 순서를 조정합니다.
- **번호 정리:** 최종 순서에 따라 두 항목을 각각 1번부터 매깁니다. `1. 제목`처럼 점 뒤 공백은 한 칸으로 맞추고, 자동 번호와 직접 입력한 번호의 중복을 정리합니다.
- **날짜 선택:** 날짜 입력칸을 클릭하면 일요일부터 시작하는 달력이 열립니다. 별도 달력 버튼 없이 직접 입력도 가능하며 요일과 결과 파일명이 자동 갱신됩니다.
- **서식 유지:** 내장 양식의 제목 도형과 날짜의 스타일·글자 모양·정렬·문단 간격·배치를 그대로 유지하고, 날짜 값과 상단 부서명만 선택 값에 맞춥니다. 상단 영역에는 본문 스타일 교정을 적용하지 않습니다. 업무의 표·그림과 본문의 내어쓰기·탭 정렬을 유지합니다.
- **최종 검사:** 문단 간격과 지정 스타일의 들여쓰기를 적용하고 수동 선행 공백을 제거합니다. Shift+Tab 내어쓰기의 왼쪽·오른쪽 여백·첫 줄 값과 탭 위치는 보존합니다. 업무 순서·개수가 맞지 않으면 저장을 중단합니다.
- **PC용 화면:** 크기 조절과 스크롤을 지원합니다. 불필요한 왼쪽 외부 스크롤바는 표시하지 않으며 입력 영역은 마우스 휠로 이동합니다. 노트북·확장 모니터를 옮기면 현재 모니터의 배율에 맞춰 글자·여백·열 너비를 갱신하고 작업 영역 안에 창을 맞춥니다. Pretendard Medium 10pt, Windows 고해상도 인식, 무채색 화면과 블랙/화이트 강조를 적용했습니다. 보조 선택 표시에만 파스텔 블루를 사용합니다.
- **단일 EXE 배포:** 한글 양식과 글꼴을 EXE에 포함하므로 직원에게 별도 양식·글꼴 설치를 요청할 필요가 없습니다.

## 실행 환경

- Windows와 설치된 Windows용 한/글이 필요합니다. EXE에도 한/글 프로그램 자체가 포함되지는 않습니다.
- 소스 실행과 EXE 빌드는 Python이 필요합니다. 검증 환경은 **Python 3.14.4 / Tk 8.6.15**입니다.
- 직원이 배포된 EXE를 실행할 때는 Python 설치가 필요하지 않습니다.

```powershell
py -m pip install -r requirements.txt
py 업무보고_자동취합.py
```

## 부서별 회의자료 만들기

1. 우측 상단에서 **생방기술1** 또는 **생방기술2**를 선택합니다.
2. **지난주 최종본**을 한 개 선택합니다.
3. **이번 주 취합 파일**에 해당 부서의 파일을 추가합니다. 지난주 최종본은 이 목록에 다시 추가하지 않습니다.
4. **업무 제목 불러오기**를 누릅니다. 자동 구분 제목이 없으면 팝업에서 부서 경계를 선택한 뒤 **선택**을 누릅니다.
5. 추진실적·추진계획의 내용을 확인하고 각 탭에서 필요에 따라 업무 순서를 변경합니다.
6. 날짜를 달력에서 선택하거나 `2026.10.20.` / `2026-10-20` 형식으로 입력합니다.
7. 저장 폴더를 선택하고 모드에 맞는 **생방기술1 최종 취합** 또는 **생방기술2 최종 취합**을 누릅니다.
8. 저장된 한글 문서를 열어 표·그림·페이지 배치를 확인합니다.

## 두 부서 최종 취합하기

1. 우측 상단에서 **생방기술국**을 선택합니다. 부서별 입력 화면 대신 최종 취합 전용 입력 화면이 표시됩니다.
2. **생방기술1 회의자료**와 **생방기술2 회의자료**에 각 부서가 완성한 파일을 한 개씩 넣습니다.
3. **업무 제목 불러오기**를 누릅니다. 두 파일에 추진실적·추진계획이 모두 있어야 하며 같은 파일을 양쪽에 넣을 수 없습니다.
4. 각 탭에서 생방기술1 → 생방기술2 순서로 불러온 내용을 확인하고, 필요하면 드래그·이동 버튼·`Alt+↑/↓`로 순서를 변경합니다. 저장할 때 변경한 순서대로 번호를 다시 매깁니다.
5. 날짜와 저장 폴더를 정하고 **생방기술국 최종 취합**을 누릅니다.

날짜가 `2026.10.24.`인 경우 파일명은 다음과 같습니다. 모드나 날짜를 바꾸면 선택한 저장 폴더 안의 파일명도 자동 갱신합니다. 같은 이름의 파일이 있으면 다른 폴더를 선택하거나 기존 결과의 이름을 바꾼 뒤 실행합니다.

| 모드 | 결과 파일명 |
| --- | --- |
| 생방기술1 | `생방기술1_회의자료_261024.hwp` |
| 생방기술2 | `생방기술2_회의자료_261024.hwp` |
| 생방기술국 | `생방기술국_회의자료_261024.hwp` |

## 문단 스타일 기준

| 문단 | 스타일 |
| --- | --- |
| 상단 제목 | 내장 템플릿의 원래 스타일·도형·배치 유지 |
| 날짜 | 내장 템플릿의 원래 스타일·정렬·배치 유지 |
| `<추진실적>`, `<추진계획>` | `추진` |
| `1.`, `2.`, `3.` … 업무 제목 | `1,2,3` |
| `-` 본문 | `-` |
| `·` 본문 | `·` |

일반 본문은 지정 스타일의 문단 서식을 적용하고 문단 앞의 수동 공백·탭으로 들여쓰기를 만들지 않습니다. 본문 안의 공백·탭·강제 줄바꿈은 유지합니다. 이미 내어쓰기(Shift+Tab)가 설정된 문단은 해당 정렬값을 보존하고 나머지 문단 서식을 지정 스타일로 맞춥니다. 기호 없이 이어지는 일반 본문에도 본문 스타일을 적용합니다.

**표 내부와 표·사진·이미지가 들어 있는 문단은 원본을 유지합니다.** 셀 안의 번호·기호·일반 문장·빈 문단과 캡션·그림 안 글상자에 본문 스타일 교정이나 선행 공백·탭 제거를 적용하지 않습니다. 표·그림이 놓인 바깥 문단의 들여쓰기·정렬·간격도 바꾸지 않습니다. 업무 제목 번호는 기존 취합 순서에 따라 다시 매기며, 표 안의 번호는 바꾸지 않습니다.

## 지난주 최종본의 부서 구분 기준

지난주 최종본에는 생방기술1 내용이 먼저, 생방기술2 내용이 그다음에 있습니다. 프로그램은 **추진계획 안의 `견학 및 기타 제작사항` 업무**를 생방기술1의 마지막 업무로 식별합니다.

- **생방기술1:** 첫 업무부터 경계 업무의 본문·표까지 포함합니다.
- **생방기술2:** 경계 업무의 본문·표를 제외하고 그다음 업무부터 가져옵니다.
- 경계 업무의 번호가 4번인지 6번인지에는 의존하지 않습니다.
- 추진실적에 같은 문구가 있어도 이월 기준으로 사용하지 않습니다.
- 경계 제목이 없으면 지난주 **추진계획의 업무 제목만** 목록으로 표시합니다. 이번 주 추진실적으로 넣을 범위를 고르는 창이므로 문구는 아래와 같습니다.
  - 생방기술1: `생방기술1의 마지막 추진실적을 선택하시오.` — 선택한 업무의 본문·표까지 포함합니다.
  - 생방기술2: `생방기술2의 첫 번째 추진실적을 선택하시오.` — 선택한 업무부터 끝까지 포함합니다.
- 목록에서 항목을 고른 뒤 **선택** 또는 Enter로 확정합니다. 취소·Esc·창 닫기는 불러오기를 중단하며 부서를 임의로 추정하지 않습니다.
- 동일한 자동 경계 제목이 여러 개면 오류를 표시하고 중단합니다.

## EXE 만들기

먼저 소스 실행으로 수정 내용을 확인한 뒤 빌드합니다. 이전 EXE가 실행 중이면 파일 교체가 잠길 수 있으므로 해당 프로그램을 닫고 실행하세요.

```powershell
py build_exe.py
```

기본 결과 위치:

```text
dist/생방기술국_회의자료_취합.exe
```

`build_exe.py`는 내장 양식, 글꼴, 글꼴 라이선스, 고해상도 매니페스트와 문서·체크 아이콘을 사용합니다. 프로그램 창·완료 팝업·EXE 아이콘에 같은 디자인을 적용하고 필요한 아이콘 파일을 EXE에 포함하므로 직원에게 별도로 전달할 필요가 없습니다. 별도의 `테스트 파일` 폴더는 빌드 입력으로 포함하지 않습니다.

일부 PC에서 프로그램과 함께 `PyInstaller Onefile Hidden Window`라는 빈 창이 보이는 경우가 있어, EXE는 시작할 때와 실행 중에 자기 부모 프로세스의 해당 보조 창만 숨깁니다. 기존 사용자에게는 다시 만든 EXE 하나를 전달하면 됩니다. 보조 창은 종료 시 임시 파일 정리를 위해 유지하며, 이 처리는 소스 실행에는 적용하지 않습니다.

## GUI 회귀 검사

실제 회의자료 없이 부서별 추출 범위·본문·표 보존과 양식 부서명을 검사하고, Windows에서 부서 선택·수동 경계 팝업·작업 스레드 응답·취소·목록 표시·순서 변경·일요일 달력·직접 입력·배율 왕복 처리를 검사할 수 있습니다.

```powershell
py -m unittest discover -s tests -v
```

다중 모니터에서는 창을 이동한 뒤 글자 크기, 목록 열 너비, 달력 위치가 현재 모니터에 맞는지도 확인하세요.

## 개발 작업 흐름

코드를 수정하면 변경에 적합한 검증을 수행하고 `docs/CHANGELOG.md`에 작업 내용을 기록합니다. 사용 방법이 바뀌면 이 README도 갱신하며, 관련 코드와 문서를 같은 저장소에 커밋·푸시합니다. 자세한 상시 작업 규칙은 [AGENTS.md](AGENTS.md)를 참고하세요.
