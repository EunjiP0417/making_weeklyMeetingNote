# 주간 회의자료 취합 조건 정리

- 작성일: 2026-10-29
- 기준: 현재 프로그램 코드 `b7d5ffb`에 구현된 동작
- 목적: 현재 동작을 검토하고, 바꿀 조건을 지정하기 위한 문서

이 문서는 희망하는 기능이 아니라 **현재 실제로 적용하는 조건**을 정리한 것입니다. 수정할 때는 `조건 07을 …로 변경`처럼 번호로 지정하면 됩니다. 표·그림 보존 규칙은 7절에 따로 정리했습니다.

## 1. 모드와 입력 화면

| 조건 | 현재 동작 |
| --- | --- |
| 01 | 모드는 `생방기술1`, `생방기술2`, `생방기술국` 세 가지입니다. 시작 시 기본 모드는 생방기술2입니다. 선택한 버튼은 검정 배경·흰색 글씨로 표시합니다. |

## 2. 생방기술1·2 모드에서 가져오는 내용

| 조건 | 입력과 결과 |
| --- | --- |
| 05 | `01 지난주 최종본`에는 지난주 파일 한 개를 별도로 선택합니다. 이 파일의 **추진계획 중 선택 부서의 업무**를 이번 주 추진실적으로 넣습니다. 지난주 추진실적은 가져오지 않습니다. |
| 06 | `02 이번 주 취합 파일`에는 해당 부서의 파일을 한 개 이상 추가합니다. 각 파일의 **추진계획만** 이번 주 추진계획으로 가져옵니다. 이 파일들에 추진실적이 있어도 취합하지 않습니다. |
| 07 | 이번 주 파일 안에서 생방기술1·2 업무를 추가로 나누지는 않습니다. 사용자가 해당 부서의 자료만 목록에 넣어야 합니다. 부서명이나 파일명으로 내용을 자동 분류하지 않습니다. |
| 08 | 지난주 최종본을 이번 주 파일 목록에 함께 넣을 수 없습니다. 같은 경로의 파일을 목록에 여러 번 추가하는 것도 막습니다. |
| 09 | 최초 실적 순서는 지난주에서 추출한 업무 순서입니다. 최초 계획 순서는 왼쪽 파일 목록 순서이며, 한 파일 안에서는 원본 업무 순서를 따릅니다. 파일 목록의 위·아래 순서를 바꾸면 업무를 다시 불러와야 합니다. |

예를 들어 지난주 계획이 `1부서 A → 1부서 B → 2부서 C → 2부서 D`라면, 생방기술2의 이번 주 실적에는 `C → D`가 들어갑니다. 이번 주 파일에 별도로 적힌 추진실적으로 대체하거나 두 내용을 합치지는 않습니다.

## 3. 지난주 추진계획의 부서 경계

### 자동으로 나누는 경우

**조건 10.** 지난주 **추진계획의 업무 제목**에 `견학 및 기타 제작사항`이 있으면 그 업무를 생방기술1의 마지막 업무로 봅니다. 제목 번호와 공백 차이는 구분 기준에 영향을 주지 않습니다. 다른 문구를 덧붙인 제목까지 유사 검색하지는 않습니다.

| 모드 | 가져오는 범위 |
| --- | --- |
| 생방기술1 | 첫 업무부터 `견학 및 기타 제작사항` 업무 끝까지 |
| 생방기술2 | 해당 업무의 **다음 업무부터** 추진계획 끝까지 |

경계 업무의 설명·표·사진 등 다음 제목 직전까지의 내용은 모두 생방기술1에 포함됩니다. 추진실적이나 표 안에 같은 문구가 있는 것은 이 경계 판정에 사용하지 않습니다.

**조건 11.** 자동 경계 제목이 여러 개면 부서를 임의로 정하지 않고 오류로 중단합니다. 생방기술2를 선택했는데 경계 뒤에 업무가 하나도 없어도 중단합니다.

### 자동 경계 제목이 없는 경우

**조건 12.** 팝업에는 지난주 **추진계획에서 식별한 업무 제목만** 표시합니다. 이번 주 추진실적으로 넣을 범위를 고르므로 안내 문구에는 `추진실적`을 사용합니다.

| 모드 | 팝업 문구 | 선택 후 가져오는 범위 |
| --- | --- | --- |
| 생방기술1 | `생방기술1의 마지막 추진실적을 선택하시오.` | 첫 업무부터 **선택 업무 끝까지 포함** |
| 생방기술2 | `생방기술2의 첫 번째 추진실적을 선택하시오.` | **선택 업무부터 포함**하여 끝까지 |

**조건 13.** 같은 제목의 업무가 있어도 목록의 위치로 구분합니다. 선택 버튼·Enter로 확정하고, 취소·Esc·창 닫기는 불러오기를 중단합니다. 취소한 경우 임의의 경계로 계속 진행하지 않습니다.

## 4. 생방기술국 최종 취합

```text
3. 생방기술2 업무
4. 생방기술2 업무

<추진계획>
1. 생방기술1 업무
2. 생방기술2 업무
3. 생방기술2 업무
```

## 6. 제목·날짜·일반 본문 스타일

**조건 25.** 결과의 기본 양식은 `assets/report_template.hwpx`입니다. 제목 도형·날짜·상단 빈 문단은 템플릿의 스타일·글자 모양·정렬·간격·배치를 유지합니다. 상단의 날짜·요일과 편집 가능한 부서 표시만 선택 값으로 바꿉니다. 도형 안 제목은 템플릿 것을 유지하며, 모드별로 새로 조합하지 않습니다.

**조건 26.** 표·그림 보존 대상이 아닌 일반 본문에는 아래 기준을 적용합니다.

| 대상 | 적용 기준 |
| --- | --- |
| `<추진실적>`, `<추진계획>` | `추진` 스타일 |
| 번호가 붙은 업무 제목 | `1,2,3` 스타일 |
| `-`로 시작하는 본문 | `-` 스타일 |
| `·`로 시작하는 본문 | `·` 스타일 |
| 기호 없는 이어지는 문단 | 원래 `-`·`·` 스타일이 있으면 해당 단계 유지. 그 외에는 직전 본문 단계에 따라 적용하며, 해당 단계가 없으면 `바탕글` 적용 |

**조건 27.** 일반 본문의 문단 앞 수동 공백·탭을 정리하고 지정 스타일의 문단 여백을 적용합니다. 본문 안의 공백·탭·강제 줄바꿈은 유지합니다. 일반 본문 전체를 한 글꼴·크기로 덮어쓰는 처리는 하지 않습니다.

**조건 28.** 이미 실제 내어쓰기가 있는 일반 본문은 왼쪽·오른쪽 여백, 첫 줄 내어쓰기 값과 탭 위치를 보존합니다. 코드에서는 문단의 첫 줄 값이 음수인지로 판정합니다. 이 경우 탭은 유지하고, 줄 간격 등 나머지 문단 서식은 지정 스타일에 맞춥니다. 스타일과 다르다는 이유만으로 모든 원본 문단 서식을 보존하지는 않습니다.

## 7. 표·사진·이미지 보존 — 본문 스타일보다 우선

**조건 29.** 표 내부에는 본문 스타일 교정을 적용하지 않습니다. 아래 내용도 모두 원본대로 유지합니다.

- 일정의 두 번째 줄·비고를 포함한 모든 셀의 내용과 들여쓰기
- 셀의 번호·하이픈·중점·일반 문장·빈 문단
- 문단 앞 공백·탭, 문장 안 공백·탭·줄바꿈
- 문단 정렬·여백·내어쓰기·줄 간격과 중첩 표
- 표 안의 번호: 바깥 업무 번호와 달리 다시 매기지 않음

**조건 30.** 표·사진·이미지가 들어 있는 **바깥 문단 전체**도 원본을 유지합니다. 개체가 놓인 줄의 들여쓰기·정렬·간격을 바꾸거나 앞 공백을 제거하지 않습니다. 같은 문단에 설명 글이 함께 있어도 해당 문단 전체를 본문 스타일 교정에서 제외합니다.

**조건 31.** 사진·이미지의 데이터, 크기·배치·자르기 정보와 표의 셀 크기·여백·병합 정보를 유지합니다. 캡션·그룹 그림·그림 안 글상자도 교정 대상에서 제외합니다. 현재 코드에서는 도형·차트·수식·동영상·OLE 개체가 들어 있는 문단도 같은 보존 대상으로 취급합니다.

**조건 32.** 위 보존 규칙이 적용되는 줄에 바깥 업무 제목 번호가 함께 있으면, **업무 번호 자체는 취합 순서대로 변경**합니다. 개체와 해당 문단의 들여쓰기는 유지합니다.

## 10. 입력 제한과 중단 조건

**조건 40. 입력 파일과 항목**

- 선택 가능한 문서는 `.hwp`, `.hwpx`입니다. Windows용 한/글이 설치되어 있어야 합니다. 배포 EXE 실행에는 Python 설치가 필요하지 않습니다.
- 부서별 모드의 이번 주 파일은 추진계획만 있어도 됩니다. 추진실적을 일부러 추가할 필요가 없습니다. 단, 이번 주 파일 전체에서 추진계획 업무를 한 개 이상 가져와야 합니다.
- 생방기술국 모드는 각 부서 파일의 추진실적·추진계획에 모두 업무가 있어야 합니다.
- 최종 생성 시에는 추진실적과 추진계획이 모두 비어 있지 않아야 합니다.

**조건 41. 구분 제목과 구역**

- 이번 주 취합 파일과 생방기술국에 넣는 부서 완성본은 단일 구역 문서를 지원합니다. 다중 구역 문서는 오류로 중단합니다.
- 지난주 최종본은 여러 구역을 읽어 부서 경계가 속한 추진계획 범위를 추출하고, 추출 사본을 한 구역으로 정리하는 별도 경로를 사용합니다. 여러 추진계획 블록을 모두 자동 연결하는 기능은 아닙니다.
- 일반 입력 문서에 같은 종류의 구분 제목이 반복되면 `구분 제목이 중복됩니다`로 중단합니다. 예를 들어 `<추진계획>`이 두 번 나오는 문서를 자동으로 합쳐 읽지 않습니다. 이번 주 파일에서 추진실적을 사용하지 않더라도 중복 구분 제목 검사는 수행합니다.
- 업무 제목이 비어 있거나 첫 업무를 식별하지 못하면 중단합니다. 업무 제목 안에 탭·필드·강제 줄바꿈이 있으면 일반 텍스트 제목으로 정리하도록 오류를 표시합니다.

**조건 42. 다시 불러오기와 최종 검사**

- 모드·파일 선택·파일 목록 순서를 바꾸면 업무 제목을 다시 불러와야 합니다. 불러오기 전에는 최종 취합할 수 없습니다.
- 원본 파일을 외부에서 수정한 경우에는 직접 `업무 제목 불러오기`를 다시 실행해야 수정 내용이 반영됩니다. 같은 경로의 파일 내용 변경을 자동 감지하지 않습니다.
- 최종 저장 전, 불러온 업무 목록의 순서·개수가 실제로 삽입된 업무와 일치하는지 검사합니다. 순서·개수가 다르거나 내부 작업 표식이 남으면 저장을 중단합니다.
- 한/글 파일 읽기·변환·삽입·저장·다시 열기에 실패하면 오류를 표시합니다.

## 11. 완료 표시와 배포 관련 동작

**조건 43.** 결과를 저장한 뒤 한/글에서 다시 열기를 확인합니다. 완료 팝업에는 저장 경로와 `최종 파일을 확인하세요.`를 표시합니다. 최종 문서의 표현·업무 내용이 올바른지는 사용자가 확인합니다.

**조건 44.** EXE는 양식·아이콘·글꼴을 내장합니다. `PyInstaller Onefile Hidden Window`가 표시되는 경우 자기 실행에 속한 보조 창만 자동으로 숨깁니다. 이 처리는 취합 내용이나 문서 서식을 바꾸지 않습니다.
