HWPX 교정 단계에서는 개체 문단 전체 XML도 일치했습니다. 실제 자료·검증 사본은 Git에서 제외했습니다.

### 일부 PC에서 표시되는 PyInstaller 숨김 보조 창 처리

- 사진의 `PyInstaller Onefile Hidden Window`는 PyInstaller 6.20.0의 단일 EXE 부모 프로세스가 Windows 종료 알림과 임시 파일 정리를 위해 만드는 보조 창임을 공식 부트로더 소스에서 확인했습니다. 현 PC의 기존 EXE는 정상·숨김 시작 설정에서 이 창을 표시하지 않았으므로, 해당 직원 PC에서 창을 드러내는 정확한 계기는 확인하지 못했습니다.
- EXE 시작 시와 실행 중 0.5초 간격으로 자신의 부모 PID·창 클래스·창 제목이 모두 일치하는 창만 확인하고, 표시된 경우 `ShowWindowAsync(SW_HIDE)`로 숨깁니다. 보조 창을 닫거나 부모 프로세스를 종료하지 않아 Windows 종료 알림과 임시 파일 정리는 유지합니다. 다른 프로그램의 보조 창·메인 화면·팝업과 소스 실행에는 적용하지 않습니다.
- README에 증상과 새 EXE 교체 안내를 추가했습니다. 문서 추출·취합·스타일 처리는 변경하지 않았습니다.
- `py -m unittest discover -s tests -v`: 총 34개 통과. 실제 Windows 창을 생성해 대상 보조 창의 숨김과 재표시 후 재숨김, 같은 제목의 다른 클래스·같은 클래스의 다른 제목·메인 창·다른 PID 창의 보존, 소스 실행에서의 미적용을 확인했습니다. 기존 부서별 추출·최종 취합·스타일·GUI 검사 31개도 통과했습니다.
- 기존 EXE의 실제 보조 창을 강제로 표시하면 계속 남아 있는 것을 확인했습니다. 새 `dist/생방기술국_회의자료_취합.exe`는 정상 표시·숨김 시작 설정 각각에서 보조 창을 두 번씩 강제로 표시해도 자동으로 다시 숨겼으며, 메인 화면 표시와 정상 종료(종료 코드 0)를 확인했습니다. 해당 직원 PC의 실제 실행 환경은 직접 검사하지 못했으므로 그 PC에서 새 EXE 교체 후 최종 확인이 필요합니다.
- EXE 내장 코드가 최종 소스와 일치하고 양식·아이콘·글꼴·라이선스가 포함된 것을 확인했습니다. 빌드 경고 없음, 문법 검사와 Git 변경 검사 통과. 실행 파일·기존 EXE 검증용 사본·빌드 로그는 Git에서 제외했습니다.

### 부서별 이월과 수동 부서 경계 선택

- 우측 상단을 동일한 크기의 `생방기술1` / `생방기술2` 선택 버튼으로 변경했습니다. 기존 사용자를 위해 시작 시 생방기술2를 선택하며, 선택 부서는 검정 배경·흰색 글씨로 강조합니다.
- 지난주 추진계획의 `견학 및 기타 제작사항`을 생방기술1의 마지막 업무로 유지합니다. 생방기술1 모드는 첫 업무부터 경계 업무의 본문·표까지, 생방기술2 모드는 그다음 업무부터 이월합니다.
- 자동 경계 제목이 없으면 지난주 추진계획의 업무 제목만 팝업 목록에 표시합니다. 사용자의 최종 요청에 따라 안내 문구는 `생방기술1의 마지막 추진실적을 선택하시오.` / `생방기술2의 첫 번째 추진실적을 선택하시오.`로 표시합니다.
- 수동 선택한 업무를 포함해 생방기술1은 처음부터 선택 업무 끝까지, 생방기술2는 선택 업무부터 끝까지 가져옵니다. 목록에서 위치로 선택하므로 동일한 제목도 구분하며, 긴 제목·많은 업무는 스크롤로 확인할 수 있습니다.
- 취소·Esc·창 닫기는 부서를 추정하지 않고 불러오기를 중단합니다. 작업 스레드와 UI 스레드는 이벤트·응답 큐로 연결하고, 완료·취소·오류 후 버튼을 복원합니다.
- 부서를 전환하면 불러온 목록과 부서 정보를 초기화하고 다시 불러오도록 안내합니다. 불러오기·문서 생성 중에는 부서 전환을 막고, 생성 시에도 불러온 부서가 현재 부서와 같은지 확인합니다.
- 결과 문서 상단의 부서명을 선택 부서로 바꿉니다. 지난주 계획을 이번 주 실적으로 이월하는 흐름과 이번 주 파일의 추진계획 취합은 유지했습니다.
- README에 부서 선택, 자동·수동 경계, 취소 및 재불러오기 절차를 갱신했습니다.

### 생방기술국 최종 취합 모드와 파일명

- 상단에 `생방1+생방2` 모드를 추가하고, 선택 시 기존 01·02 입력 대신 두 부서의 완성된 회의자료를 한 개씩 넣는 별도 입력 화면을 표시합니다. 날짜·저장 위치·목록 탭·로그 등 전체 화면 구성은 공유합니다.
- 최종 모드는 지난주 계획을 다시 이월하지 않고 두 결과 파일의 추진실적·추진계획을 각각 읽습니다. 실적은 생방기술1 실적 다음 생방기술2 실적, 계획은 생방기술1 계획 다음 생방기술2 계획으로 연결합니다.

- 추진실적은 지난주 순서로 처음 불러오고, 두 탭 모두 드래그·버튼·키보드로 순서를 조정할 수 있습니다.
- 최종 순서에 따라 각 항목을 독립적으로 `1. 제목` 형식으로 매깁니다.
- 자동 번호와 수동 번호가 혼재했을 때 중복 번호를 정리합니다.
- 불필요한 빈 문단을 정리하고 업무 사이에 빈 문단 하나를 둡니다.
- 제목·날짜·구분 제목은 내장 양식을 사용합니다.
- 최종 스타일 검사에서 본문의 직접 지정 내어쓰기와 탭 정렬을 덮어쓰지 않도록 수정했습니다.
- 표와 그림은 한/글의 문서 삽입을 통해 가져오며, UUID 표식으로 삽입 순서·개수를 검사합니다.

### 날짜와 화면

- 날짜 직접 입력과 달력 선택을 함께 지원합니다.
- 입력 날짜의 실제 요일과 `생방기술국_회의자료_YYMMDD.hwp` 파일명을 자동 갱신합니다.
- 고정 모바일 화면 대신 창 크기 변경과 스크롤을 지원하는 PC용 카드 구성을 적용했습니다.
- 기본 글자를 9pt에서 10pt로 확대했습니다.
- 본문을 Pretendard Medium, 검정·진회색 글자로 조정했습니다.
- 화면은 화이트·그레이·블랙을 기본으로 하고, 주요 버튼·선택 탭은 블랙 배경과 화이트 글씨로 강조합니다.
- 업무·달력의 보조 선택 표시에만 톤 다운된 파스텔 블루(`#DCE6F0`)를 사용합니다.
- PY 실행 시 Tk 창 생성 전에 DPI 인식을 설정하고, EXE에는 PerMonitorV2 매니페스트를 포함했습니다. 글자와 여백을 화면 배율에 맞춰 직접 렌더링합니다.

### 배포

- 한글 양식, Pretendard Regular·Medium·Bold, 글꼴 라이선스를 단일 EXE에 포함합니다.
- 실제 회의자료와 테스트 산출물, EXE 및 백업 파일은 Git에서 제외합니다.
- 사용 중인 EXE가 잠긴 경우 기존 프로그램을 강제로 종료하지 않고 별도 업데이트 EXE를 생성해 검증했습니다.
