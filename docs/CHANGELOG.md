# 변경 및 검증 기록

## 2026-10-20

### 완료 팝업 문구와 통일 아이콘

- 완료 팝업에 저장된 파일의 전체 경로·이름을 표시하고, 그 아래에 `최종 파일을 확인하세요.`를 표시하도록 변경했습니다.
- 사용자가 선택한 `문서 + 체크` 디자인을 무채색 SVG로 자체 제작하고 PNG와 16~256px 다중 해상도 ICO로 저장했습니다.
- 프로그램 창·완료 팝업 제목 표시줄·팝업 본문·EXE에 같은 아이콘을 적용했습니다. 날짜 선택 창에도 같은 창 아이콘을 적용하고 Windows 작업 표시줄 식별자를 지정했습니다.
- 완료 팝업을 앱 스타일의 창으로 구성해 긴 경로를 줄바꿈하고, 소유 창의 모니터 안에 표시하며 확인 버튼·Enter·Esc로 닫을 수 있게 했습니다.
- `build_exe.py`에서 아이콘 자산 존재 여부를 확인하고 EXE 아이콘과 내장 PNG·ICO를 함께 포함하도록 수정했습니다. README의 빌드 자산 안내를 갱신했습니다.
- 기존 GUI 검사 9개가 모두 통과했습니다. 실제 175%·100% 모니터에서 완료 이벤트의 경로·문구, 창 아이콘 픽셀 일치, 팝업 본문 아이콘, 위치, 확인·Esc와 버튼 상태 복원을 확인했습니다.
- 새 EXE의 내장 코드가 최종 소스와 일치하고 모든 ICO 이미지 리소스가 원본과 일치하는지 확인했습니다. 내장 자산과 고해상도 설정, 정상 실행·종료도 확인했습니다.
- 최종 EXE를 기본 배포 경로에 갱신하고 `dist`에는 실행 파일 하나만 유지했습니다.

### 배포 폴더 정리

- 버튼 크기 조정과 저장 위치 안내를 포함한 최종 EXE를 생성하고, 내장 코드의 최종 소스 일치·양식·글꼴·고해상도 설정 포함 및 정상 실행·종료를 확인했습니다.
- 사용자 요청에 따라 `dist`의 이전 EXE, 백업, 중간 빌드 폴더를 삭제했습니다. 실제 사용자 문서는 없고 실행 중인 EXE도 없는 것을 확인한 뒤 `dist` 내부만 정리했습니다.
- `dist/생방기술국_회의자료_취합.exe` 하나만 남기고 검증된 빌드와 SHA256이 일치하는지 확인했습니다.

### 저장 위치 안내 표시

- 저장 폴더를 선택하지 않았을 때 경로 칸에 `저장 폴더를 선택하세요`를 표시하고, 선택 후에는 실제 저장 경로와 파일명을 표시하도록 했습니다.
- 화면 표시용 변수를 실제 저장 경로와 분리해 안내 문구가 파일 경로로 처리되지 않게 했습니다.
- 실제 GUI에서 미선택 상태와 선택 취소 시 안내 유지, 폴더 선택 후 실제 경로 표시, 날짜 변경 시 파일명 동기화, 경로 초기화 후 안내 복원을 확인했습니다.

### 업무 제목 불러오기 버튼 크기 조정

- `업무 제목 불러오기`는 검정 배경·흰색 글씨를 유지하면서 `추가`·`삭제`와 같은 본문 글꼴과 안쪽 여백을 사용하도록 조정했습니다.
- 최종 회의자료 만들기 버튼의 크기와 스타일은 유지했습니다.
- 문법 검사와 실제 GUI 검사에서 100%·175% 배율의 불러오기/추가/삭제 버튼 높이가 각각 32px·53px로 일치하고 글꼴·여백이 같은지 확인했습니다. 기본·호버·누름·비활성 상태와 기존 불러오기 함수 연결도 확인했습니다.

### 입력 버튼 강조와 저장 위치 배치

- 01 지난주 최종본의 선택 버튼 문구를 `추가`로 변경했습니다. 기존 지난주 최종본 선택 동작은 유지했습니다.
- 02의 `업무 제목 불러오기`에 검정 배경·흰색 글씨의 주요 실행 버튼 스타일을 적용했습니다. 마우스 호버·누름 상태에서도 흰색 글씨를 유지하고 실행 중 비활성 상태는 회색으로 구분합니다.
- 03은 날짜, `저장 폴더 선택` 버튼, 선택한 저장 폴더 경로 순서로 배치했습니다.
- 문법 검사와 실제 GUI 검사에서 버튼 문구·연결 함수, 기본·호버·누름·비활성 색상, 날짜/버튼/경로의 배치, 날짜 직접 입력과 달력 열기를 확인했습니다.
- EXE를 갱신했으며 내장 코드가 최종 소스와 일치하고, 양식·글꼴·고해상도 설정이 포함되며 정상 실행·종료되는지 확인했습니다.

### 화면 안내 문구 정리

- 01 설명을 `지난 주 계획을 이번 주 실적으로`로 변경했습니다.
- 02 설명 `각 파일의 추진계획을 가져옵니다`는 유지했습니다.
- 03의 날짜 입력 안내 문구를 삭제하고 날짜 칸과 저장 위치 사이 여백을 정리했습니다.
- 오른쪽 영역의 제목을 `업무 순서`에서 `회의자료 순서`로 변경했습니다.
- 문법 검사와 실제 GUI 위젯 검사에서 변경 문구, 날짜 직접 입력에 따른 요일 갱신, 날짜 칸 클릭으로 달력 열기를 확인했습니다.
- EXE를 갱신하고 최종 문구·내장 양식·글꼴·고해상도 설정 포함 여부와 프로그램 시작·정상 종료를 확인했습니다.

### 업무 목록·달력·다중 모니터 개선

- 업무 목록을 `업무 제목` / `파일명` 두 열로 분리했습니다. 제목에 파일명을 이어 붙이지 않으며 열 폭을 조절할 수 있습니다.
- 두 열 모두 드래그로 순서를 바꿀 수 있고, 위·아래 버튼과 `Alt+↑/↓`를 유지했습니다. 열 제목·빈 공간 클릭과 영역 밖 드롭은 잘못된 순서 변경을 만들지 않습니다.
- 달력은 `일 월 화 수 목 금 토` 순서로 표시하고 별도 달력 버튼을 제거했습니다. 날짜 칸 클릭, 직접 입력, 자동 요일·파일명 갱신을 유지했습니다.
- 왼쪽 입력 영역 옆의 긴 외부 스크롤바를 제거하고 작은 창에서 마우스 휠 이동을 유지했습니다.
- 시작 모니터의 배율을 고정해 쓰는 대신 현재 창의 DPI와 모니터 작업 영역을 확인하도록 수정했습니다.
- 모니터 이동 시 이름 있는 글꼴을 재설정하고, 여백은 원래 값을 기준으로 계산해 반복 왕복 때 누적 확대되지 않게 했습니다. 목록 열 너비와 행 높이도 함께 갱신합니다.
- 서로 다른 DPI에서 창 테두리 보정이 누적되는 문제는 실제 클라이언트 크기로 창을 맞추어 해결했습니다. 최대화 상태는 유지하고 복원 창은 해당 모니터 작업 영역에 맞춥니다.
- 음수 좌표에 있는 확장 모니터에서도 달력이 날짜 칸 근처의 같은 모니터에 표시되도록 수정했습니다.
- `tests/test_ui.py`에 Windows GUI 회귀 검사 9개를 추가했고 모두 통과했습니다.
- 실제 노트북 175% / 확장 모니터 100%에서 반복 이동, 최대화·복원, 창 크기·글꼴·여백의 왕복 안정성과 업무 선택·날짜 유지 및 달력 위치를 확인했습니다.
- 새 EXE에서도 내장 자산·고해상도 모드·시작/종료 및 실제 두 모니터 간 이동을 확인했습니다. 기본 창의 클라이언트 크기는 100%에서 1180×850, 175%에서 2065×1488로 유지됐습니다.
- 문서 취합·번호·표·들여쓰기 처리 함수는 변경하지 않았습니다.

### 순서와 문서 서식

- 추진실적은 지난주 순서로 처음 불러오고, 두 탭 모두 드래그·버튼·키보드로 순서를 조정할 수 있습니다.
- 최종 순서에 따라 각 항목을 독립적으로 `1. 제목` 형식으로 매깁니다.
- 자동 번호와 수동 번호가 혼재했을 때 중복 번호를 정리합니다.
- 불필요한 빈 문단을 정리하고 업무 사이에 빈 문단 하나를 둡니다.
- 제목·날짜·구분 제목은 내장 양식을 사용합니다.
- 최종 스타일 검사에서 본문의 직접 지정 내어쓰기와 탭 정렬을 덮어쓰지 않도록 수정했습니다.
- 표와 그림은 한/글의 문서 삽입을 통해 가져오며, UUID 표식으로 삽입 순서·개수를 검사합니다.

### 날짜와 화면

- 날짜 직접 입력과 달력 선택을 함께 지원합니다.
- 입력 날짜의 실제 요일과 `생방기술국_회의자료_YYMMDD.hwp` 파일명을 자동 갱신합니다.
- 고정 모바일 화면 대신 창 크기 변경과 스크롤을 지원하는 PC용 카드 구성을 적용했습니다.
- 기본 글자를 9pt에서 10pt로 확대했습니다.
- 본문을 Pretendard Medium, 검정·진회색 글자로 조정했습니다.
- 화면은 화이트·그레이·블랙을 기본으로 하고, 주요 버튼·선택 탭은 블랙 배경과 화이트 글씨로 강조합니다.
- 업무·달력의 보조 선택 표시에만 톤 다운된 파스텔 블루(`#DCE6F0`)를 사용합니다.
- PY 실행 시 Tk 창 생성 전에 DPI 인식을 설정하고, EXE에는 PerMonitorV2 매니페스트를 포함했습니다. 글자와 여백을 화면 배율에 맞춰 직접 렌더링합니다.

### 배포

- 한글 양식, Pretendard Regular·Medium·Bold, 글꼴 라이선스를 단일 EXE에 포함합니다.
- 실제 회의자료와 테스트 산출물, EXE 및 백업 파일은 Git에서 제외합니다.
- 사용 중인 EXE가 잠긴 경우 기존 프로그램을 강제로 종료하지 않고 별도 업데이트 EXE를 생성해 검증했습니다.
